=== [about] https://docs.elicit.com/
Elicit API Reference 
 Elicit API
 OpenAPI Version:   3.1.0 
 API Version:   2.0.0 
 The Elicit API lets you search academic papers and clinical trials, run research workflows, and manage your library and shared projects.
 Getting started
 This reference documents v2 , with production base URL https://elicit.com/api/v2 . Paths below are relative to that base. The older v1 API uses different paths and response envelopes; do not mix v1 examples with this reference.
 Use an Elicit account with API access (Pro or above) and create an API key in account settings .
 Set ELICIT_API_KEY in your environment. Keep it secret; do not embed it in browser code or commit it to source control.
 Make a search request:
 curl --fail-with-body https://elicit.com/api/v2/search/papers \
 -H "Authorization: Bearer $ELICIT_API_KEY " \
 -H "Content-Type: application/json" \
 -d '{"query":"effects of sleep deprivation on cognitive performance","maxResults":10}' 
 The response contains papers and may include non-fatal warnings ; inspect warnings even on a successful response. Search returns results in the same request; research workflows return a session to poll instead.
 Choose an endpoint
 Goal 
 Start here 
 Search papers or clinical trials 
 POST /search/papers or POST /search/trials 
 Generate a report from a question 
 POST /sessions/reports 
 Configure search, screening, extraction, and reporting stages 
 POST /sessions/systematic-reviews 
 Run interactive research with follow-up messages and artifacts 
 POST /sessions/agents 
 Find existing sessions or resume quota-paused work 
 GET /sessions ; follow links.self or links.resume 
 Save papers, import PDFs, or organize collections 
 /library/sources , /library/imports , and /library/collections 
 Browse or share existing projects 
 GET /projects and POST /projects/{projectId}/shares 
 Schedule recurring Research Agent work 
 /routines 
 Check account usage 
 GET /usage 
 Authentication
 All API requests require a Bearer token in the Authorization header:
 Authorization : Bearer elk_live_your_key_here 
 API keys can be created and managed from your Elicit account settings .
 Billing
 API access requires a Pro plan or above. Your plan limits results per search request , not requests per day. Exceeding the plan's maxResults cap returns 400 invalid_request ; see the Search endpoints for the per-plan limits.
 All endpoints share a burst limit of 100 requests per minute per IP address , including polling requests. Exceeding it returns 429 and blocks that IP for 5 minutes . Coordinate polling across concurrent sessions and clients behind the same IP.
 An exhausted usage allowance returns 402 insufficient_quota when starting work ( error.details.reason is credits_exhausted or, for an organization member over their weekly spend limit, spend_limit_reached ; error.details.resetsAt is when the block lifts), or pauses a running session with status: "pausedForInsufficientQuota" . Check GET /usage , resolve the limit, then POST to links.resume ; paused work does not automatically resume. Usage reporting can return 409 for accounts without usage reporting or while their usage data is not ready.
 Manage your plan in account settings .
 Code Examples
 Working examples in curl, Python, and JavaScript, plus integrations (CLI tool, Slack bot, Claude Code skill):
 github.com/elicit/api-examples 
 Error Handling
 Application errors use this JSON envelope. Branch on the HTTP status and error.code , not the wording of error.message :
 { "error" : { "code" : "invalid_request" , "message" : "body.query: Required" } }
