 FAQs
 Answers to our most common questions.
 Why can't I just let my model read the PDF? Claude and GPT have vision now. 
 For one clean file, go ahead. But across thousands of messy docs that keep changing, the model burns tokens fighting the layout instead of answering. Unstructured cleans and structures them first, so you get better answers for less.
 Are you just a PDF parser? 
 Nope. PDFs are one of 50+ file types, alongside Word, Excel, PowerPoint, email, HTML, images, and scans, all through one pipeline. Whatever format your data shows up in, it comes out clean and structured.
 Okay, so it parses the file. Isn't that the whole job? 
 Parsing is the easy part. The real work is connecting to your sources, then chunking, embedding, and loading the result into your database, on a schedule, at scale. A parser handles one file. Unstructured runs the whole pipeline.
 Can it pull straight from my S3 or SharePoint and land in my vector DB? 
 Yes. Connect to 20+ sources (S3, SharePoint, Drive, Snowflake, Databricks, and more) and write to 20+ destinations, including every major vector database. You connect the ends; the pipeline runs between them. No glue code.
 Can I trust you with regulated data? 
 Yeah, this is built for regulated data. It's SOC 2 Type 2, HIPAA, GDPR, ISO 27001, and FedRAMP High and it can run on shared Business SaaS, a dedicated isolated instance, or fully in your own VPC. If your security or compliance team wants the full picture, book a call and we'll walk you through it.
 What do people actually build with this? 
 Depends on your industry. Finance teams pull fields off loan files and contracts and stand up research copilots; insurance turns claims and forms into clean, structured data; legal extracts and checks contract terms; life sciences preps research papers for discovery; manufacturing makes dense technical manuals searchable. Different industries, same job: turn a pile of messy documents into something an AI can actually use.

 Parse your first document
 Open in ChatGPT 
 Log in to Transform, upload a document, then Parse its content. Optionally, Extract structured data and use Get Code to build an integration.
 Open in ChatGPT 
 Transform turns documents into parsed content and structured data. Use the web app walkthrough below, or skip to your first API request to start with code. You do not need to complete both paths. 
 1
 Log in
 Log in to Transform . If you do not have access, contact your account team. 
 2
 Upload a document
 Upload your own document or download the ACME Corp Annual Report sample PDF to try the flow. Check the supported file types if you are unsure whether your file is supported. 
 3
 Parse the document
 Choose Parse . When processing finishes, review the parsed content alongside your document. 
 4
 Extract structured data (optional)
 Choose Extract if you need specific fields as structured data. Define the fields you need, then review the extracted values. 
 5
 Use Get Code
 Open Get Code to carry the flow into an API integration. Use your API key when running the code in your application.
See integrate with Get Code for the next steps. 
 ​ 
 Review the output 
 Compare the parsed content and any extracted values with your source document. See result interpretation for details. 
 See recovery guidance if an upload or processing step fails. 
 ​ 
 Make your first API request 
 You can Parse a document directly through the API without uploading it in the web app first. 
 The -i option prints response headers so you can retain Location if processing continues. Use your API key in UNSTRUCTURED_API_KEY and a supported document saved as document.pdf . No workspace parameter is required. 
 To try the example without your own file, download the ACME Corp Annual Report sample PDF and save it as document.pdf in your project directory. 
 export UNSTRUCTURED_API_KEY = "your-api-key" 
 curl -i https://transform.unstructured.io/api/v2/parse \ 
 -H "unstructured-api-key: $UNSTRUCTURED_API_KEY " \ 
 -F "input=@document.pdf" 
 A synchronous request keeps the connection open until parsing finishes. Multi-page documents can take about a minute or longer. That wait is expected. For an immediate response, see asynchronous processing . 
 HTTP 200 returns a Parse result directly. We captured this response from the ACME sample PDF on September 12, 2026. We shortened the Markdown and replaced the result ID with an example UUID:
