 Frequently Asked Questions
 Key information on security, deployment, and platform capabilities.
 What is Superblocks? 
 Superblocks is the enterprise AI vibe coding platform that lets anyone build business apps on private enterprise data, while enforcing your organization’s security, compliance, and governance policies.
 Builders use Clark, an AI coding agent, to prompt and build internal applications in natural language and then deploy securely. Admins can configure integrations, data access control, application permissions, audit logs, and more ensuring builders operate in a controlled environment that meets IT standards. 
 How does Clark AI work?
 Clark is the AI coding agent for building secure internal apps on top of private enterprise data. Clark works on top of your organization’s knowledge graph - including data schemas, API documentation, agent memory, existing app patterns, and integration configurations. Unlike general-purpose AI coding tools, Clark operates within your existing user permissions across systems like Postgres, Snowflake, Salesforce, and Databricks, with built-in governance so it can only access and generate code using data each builder is authorized to see.

 Do I own the code generated when building Superblocks apps?
 Yes - you fully own all code generated in Superblocks and connect it to your git repository.
 How does Superblocks keep my data secure?
 Superblocks is SOC 2 Type II certified and HIPAA compliant, with a security architecture designed for regulated industries. Superblocks offer VPC deployment options so the infrastructure runs entirely within your AWS, GCP or Azure environment. The platform enforces granular RBAC, SSO/SAML authentication, SCIM user group syncing, secrets manager integration, and comprehensive audit logging across every application and user action.
 How can I deploy Superblocks?
 Superblocks is built to integrate seamlessly into enterprise environments, with flexible deployment options that balance speed, security, and compliance Superblocks offers three deployment models:
 Cloud – All data and AI inference run in the Superblocks Cloud
 Hybrid – Production data remains in the customer VPC for deployed apps, while only non-production data is accessed by Clark in the Superblocks Cloud
 Cloud-Prem – The full Superblocks platform, including AI inference, is deployed within your AWS, GCP, or Azure environment and fully managed by Superblocks

 Superblocks is designed so that anyone - operations teams, data analysts, business users and domain experts - can build production-grade internal tools using natural language.

 Introduction to Superblocks
 Superblocks is the platform to build and govern AI-generated internal apps. Business teams generate production apps on your company data with AI, while IT manages integrations, authentication, access controls, auditing, and policies from one place. 
 ​ 
 The Software Factory for Business Teams. Governed by Security & IT. 
 Import from Claude, Lovable, Replit and code. Build with the Superblocks MCP. Built on your own stack – database, security tooling, inference and more. 
 ​ 
 AI Apps never access business systems directly 
 Superblocks is your integration control layer . It handles authentication, access controls, secrets management across databases, SaaS applications, and your internal APIs. Every database query and API call is centrally audited, so Admins have complete visibility. This lets business teams build quickly while IT keeps a consistent security and compliance posture. Learn more in Integrations . 
 ​ 
 Go from Claude to Prod with a single prompt 
 Superblocks in Claude lets business users turn prototypes into production apps with a single prompt, without leaving Claude. Apps open in Claude’s built-in browser, and Superblocks applies your org’s skills, standards, policies, and security rules to every prompt. 
 Identity-aware. Claude acts as you. Your SSO identity maps to your Superblocks permissions, so builders only do what their role allows.
 Governed integrations. Imported apps use your connected integrations and platform-managed authentication and RBAC instead of hardcoded credentials.
 Code Security. Publishing runs Code Security policies before anything ships.
 ​ 
 A secure, isolated database for every app 
 Superblocks Database gives every app its own Aurora PostgreSQL database inside your AWS account. Clark provisions it when an app needs to store data, and the data stays on your infrastructure. 
 Automatic provisioning for every app. Builders describe what they need to store, and Clark creates the database. No tickets and no manual setup.
 Isolated databases for each app and environment. Each app gets its own database, and development and production stay separate so test data never reaches production.
 Schema management and migrations. Clark keeps the schema in the app, and Superblocks applies those migrations on deploy.
 Sharing with granular permissions. Share a database and control exactly who can use it.
 Smart packing. Apps share clusters so infrastructure costs stay low, and Superblocks adds another cluster as the pool fills.
 Automatic isolation for high-traffic databases. A busy database is isolated so it doesn’t affect the others.
