 FAQ
 What is Open Interpreter? A coding agent that lives in your terminal. Open a project, type `interpreter`, and it can read files, edit code, run commands, and ask before it escalates beyond the current sandbox. Getting started Interactive mode 
 Which models can I use? Built-in providers include OpenAI, Amazon Bedrock, Ollama, and LM Studio.
 The generated provider catalog includes hosted providers such as Anthropic, OpenRouter, DeepSeek, Moonshot/Kimi, Z.ai, Alibaba/Qwen, Groq, and others.
 Custom providers can use Responses-compatible, OpenAI-compatible chat, or Anthropic Messages-compatible wire APIs.
 Harness modes can shape requests for Claude Code, Kimi CLI, Qwen Code, DeepSeek TUI, SWE-agent, or a minimal chat-tool surface.
 Providers Harness 
 How does the sandbox work? Sandbox mode and approval policy are separate controls. Permission profiles can allow read-only work, workspace writes, or full access; network starts disabled in permission profiles unless you enable it. When a command or tool needs approval, the TUI shows the request before it runs. Sandbox & approvals Permissions 
 Can I run multiple sessions at once? Yes. Open one terminal tab per coding session, then use `/resume`, `/fork`, or `/side` inside the TUI, or `interpreter resume` and `interpreter fork` from the shell. Interactive mode Sessions 
 How do AGENTS.md, skills, and MCP fit in? Use AGENTS.md for stable project instructions, skills for repeatable procedures, and MCP servers for explicit external tools such as issue trackers, private docs, databases, or internal CLIs. AGENTS.md Skills MCP 
 Is it really open source? Yes. Open Interpreter is open source under the Apache 2.0 License. The terminal product is a fork of Codex and keeps the Codex terminal surface while staying provider agnostic. Project license Migration 
 Is my code private? Local models stay on your machine. If you use your own API key, requests go directly from your device to that provider — not through our servers. If you use hosted models, your requests are routed through our servers and logged for up to 30 days; see our Privacy Policy . Privacy policy Providers

 Get started with Interpreter
 Interpreter is a desktop agent for work that crosses apps, files, browser tabs, spreadsheets, PDFs, and documents. It opens the apps you already use, reads the files you point at, and gets work done on your computer while you watch (or step away).
 Get help from the team 
 Who it is for
 Knowledge workers in finance, legal, ops, research, and support who spend hours each week moving information between apps. You stay in control: Interpreter pauses for review before anything that submits, sends, deletes, or overwrites.
 What it can do
 Read and edit files in a workspace you choose — PDFs, DOCX, spreadsheets, plain text, images.
 Open and operate desktop apps the way you do: clicks, typing, menus, dialogs.
 Run web tasks across portals, dashboards, CRMs, and internal tools.
 Extract structured data from documents and write it into the format you need.
 Use your voice for hands-free instructions and follow-ups.
 Plug into your stack through MCP servers and built-in integrations.
 Where to start
 If you have not installed it yet, start with Install . If you have, jump to Your first task and pick one concrete workflow to try.
 Want a feel for what it is good at before you start? Browse use cases by industry — each industry page has real workflows with the apps they touch and the exact instruction to type.
 Keep control
 Interpreter is most useful when you give it a narrow workspace, a clear output, and explicit review points before irreversible actions. Approvals and safety covers how to set that up so the agent moves fast without surprising you.

## Installation

macOS and Linux:

```bash
curl -fsSL https://www.openinterpreter.com/install | sh
```

Windows:

```powershell
irm https://www.openinterpreter.com/install.ps1 | iex
```

Then type `i` or `interpreter` in your terminal to start a session.

## Harness Emulation

Open Interpreter is a fork of OpenAI's Codex, with a focus on emulating the agent harness that gets the best performance out of low-cost models.

Use `/harness` to switch the active harness:

```text
> /harness

native
claude-code
claude-code-bare
zcode
kimi-code
kimi-cli
qwen-code
deepseek-tui
swe-agent
minimal
```

Read more in the [harness docs](https://www.openinterpreter.com/docs/terminal/harness?utm_source=github&utm_medium=referral&utm_campaign=readme&utm_content=harness_docs) and [provider setup guides](https://www.openinterpreter.com/docs/terminal/providers?utm_source=github&utm_medium=referral&utm_campaign=readme&utm_content=provider_guides).

## ACP compatible, Codex compatible

Open Interpreter works in [ACP-compatible editors and clients](https://agentclientprotocol.com/get-started/clients). Configure the client to launch `interpreter acp`; see the [ACP guide](https://www.openinterpreter.com/docs/terminal/acp) for examples.

Already building with OpenAI's Codex SDK? Keep the SDK and make a one-line
binary override:

```diff
-const codex = new Codex();
+const codex = new Codex({ codexPathOverride: "interpreter" });
```

Open Interpreter speaks the same Codex exec protocol. See the [SDK guide](https://www.openinterpreter.com/docs/terminal/sdk) and run `scripts/test-codex-sdk-compat.sh` for a local, provider-free compatibility check.

Want a small browser UI over raw Open Interpreter? Start with the
[local streaming web chat guide](docs/streaming-web-chat.md). For a complete
desktop, browser, or headless client, use
[Interpreter Workstation](https://github.com/openinterpreter/interpreter-workstation).

## Portable by default

Open Interpreter should fit into your existing agent setup instead of trapping
it in an Open Interpreter-only format. The product goal is to prefer shared,
tool-neutral standards and directories, keep user-authored data in readable
files, and make moving to or from another compatible agent straightforward.
